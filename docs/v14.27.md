# Changes in v4 / Discord.js 14.27

SelfbotJS v4 updates the fork from its previous Discord.js 14.21-compatible surface to Discord.js 14.27.0. It keeps the
fork-specific user-account APIs while adding the public exports, structures, events, and behaviors needed by code written
for Discord.js 14.27.

> Selfbots violate Discord's Terms of Service and can result in account termination. Never share or commit a user token.

## Runtime and package changes

- The npm package and import name is now `selfbotjs`.
- The package version is `4.0.0`; `discordJsVersion` reports the compatibility target (`14.27.0`).
- Node.js 20.18 or newer is required. CI covers Node.js 20, 22, and 24.
- Discord.js companion packages are aligned with the versions used by Discord.js 14.27.0 where they are part of this
  fork's public surface.

## Discord.js 14.27 parity

### New API surface

- Voice messages can be sent with an Ogg/Opus attachment containing waveform and duration metadata and the
  `IS_VOICE_MESSAGE` message flag.
- `Guild#maximumStageBitrate` exposes the maximum stage-channel bitrate.
- `Interaction#authorizingIntegrationOwners` is now an `AuthorizingIntegrationOwners` structure with guild/user IDs and
  cached `guild` and `user` accessors.
- `RoleManager#fetchMemberCounts()` fetches role subscription member counts.
- `voiceServerUpdate` is emitted with the raw gateway voice-server update data.
- `GuildMember#collectibles` includes collectible nameplate data when Discord supplies it.
- `Message#sharedClientTheme` reads shared themes, and `sharedClientTheme` can be supplied when creating a message.
- `Application#fetchActivityInstance(instanceId)` returns `ActivityInstance`, including its `ActivityLocation` and users.

### Compatibility exports

- Modern event names are available through `Events`, including `Events.ClientReady`, `Events.WebhooksUpdate`, and
  `Events.VoiceServerUpdate`. Legacy `ready` and `webhookUpdate` listeners continue to work.
- Modern numeric partials are available through `Partials`; legacy string partials remain accepted.
- Common v14 names are aliased to fork implementations: `AttachmentBuilder`, `BaseChannel`, `IntentsBitField`,
  `MessageFlagsBitField`, `PermissionsBitField`, and `UserFlagsBitField`.
- Builders, formatters, REST, utility, WebSocket, and Discord API type exports are re-exported from the package root.
- `HolographicStyle` provides the v14-style `Primary`, `Secondary`, and `Tertiary` role color values.

## Components and modals

- Component types now include label, file upload, radio group, checkbox group, and checkbox inputs.
- `LabelComponent` represents a label and its nested input.
- `ModalInputComponent` represents the new modal-only input types and supports setting scalar or multiple values.
- Modal submission parsing is recursive, so nested labels and action rows are resolved correctly.
- `ModalSubmitFieldsResolver` adds helpers for string selects, file uploads, radio groups, checkbox groups, and checkboxes.
- Modal replies preserve nested component shape and serialize `value` and `values` correctly.

## Poll updates

- `Poll` and `PollAnswer` can be partial when vote events arrive for uncached messages, polls, or answers.
- Add `Partials.Poll` and `Partials.PollAnswer` (plus their legacy string equivalents) to receive those partial vote events.
- `Poll#fetch()` hydrates a partial poll from its message.
- `PollAnswer#voters` is a `PollAnswerVoterManager` with a cache and `fetch()` method.
- Vote add/remove events update the voter cache and never decrement a vote count below zero.

## Fixes and behavior changes

- The v14 `clientReady` and `webhooksUpdate` event names are emitted alongside their legacy equivalents.
- Stage instance creation resolves `guildScheduledEvent` through the guild scheduled-event manager.
- Passing `null` for secondary or tertiary role colors now clears the gradient color.
- `GuildMember#joinedTimestamp` becomes `null` for a missing or invalid join date instead of `NaN`.
- `Message#pinnable` checks `READ_MESSAGE_HISTORY` and `PIN_MESSAGES`, and excludes voice channels.
- Attachment spoiler detection recognizes both the `SPOILER_` prefix and Discord's spoiler attachment flag.
- Attachment flags now include clip, thumbnail, remix, spoiler, and animated values.
- Gateway `RATE_LIMITED` packets produce debug output and a one-time process warning per affected opcode.
- Team members always initialize the legacy `permissions` array.
- Guild-channel manageability and empty `@everyone` overwrite checks follow the corrected 14.27 permission behavior.
- Interaction response updates accept an omitted options object, matching the upstream 14.27 fix.
- Declaration fixes include raw message data and direct-message send return types where applicable to this fork.

## Dependency alignment

The v4 runtime uses the Discord.js 14.27 companion ranges for `@discordjs/builders` 1.14.1, `@discordjs/rest` 2.6.2,
`@discordjs/util` 1.2.0, `@discordjs/ws` 1.2.3, `@discordjs/formatters` 0.6.2,
`discord-api-types` 0.38.49, `undici` 6.27.0, and `tslib` 2.6.3. `@discordjs/collection` is pinned to 1.5.3,
the exact major used by Discord.js 14.27, rather than silently moving consumers to Collection v2.

## Migration examples

Use the new package name and modern event constants:

```js
const { Client, Events, Partials } = require('selfbotjs');

const client = new Client({
  partials: [Partials.Message, Partials.Poll, Partials.PollAnswer],
});

client.once(Events.ClientReady, readyClient => {
  console.log(`${readyClient.user.tag} is ready`);
});

client.login(process.env.DISCORD_TOKEN);
```

The old string events and partial names remain available for gradual migration, but new code should prefer the v14 names.

## Upstream reference

The upstream change list is available in the
[Discord.js 14.27.0 release notes](https://github.com/discordjs/discord.js/releases/tag/14.27.0). SelfbotJS implements the
parts applicable to this fork; bot-only guide and webhook typing changes do not alter the selfbot runtime API.
